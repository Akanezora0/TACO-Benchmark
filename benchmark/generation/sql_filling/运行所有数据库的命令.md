# 运行所有数据库的SQL填充命令

## 完整命令

```bash
cd /home/u2023103807/TACO/benchmark/generation/sql_filling

python3 2fill_sql_placeholders_improved.py \
    --database_dir ../../data/beijing/database_chinese \
    --skeleton_dir ../../data/beijing/output/sql_skeleton \
    --graph_dir ../../data/beijing/output/graph_chinese \
    --output_dir ../../data/beijing/output \
    --max_retries 3
```

## 命令说明

- `--database_dir`: 数据库目录（包含所有数据库的JSON和DB文件）
- `--skeleton_dir`: SQL骨架目录（包含所有数据库的SQL骨架文件）
- `--graph_dir`: 图文件目录（包含所有数据库的图文件）
- `--output_dir`: 输出目录（结果会保存在 `output/single/{数据库名}/` 下）
- `--max_retries`: 最大重试次数（默认3次）

## 运行特性

1. **自动处理所有数据库**: 脚本会自动扫描 `skeleton_dir` 下的所有 `*_sql_skeleton.json` 文件
2. **并发处理**: 每个数据库内部使用20个线程并发处理SQL骨架
3. **断点续传**: 已存在的文件会自动跳过，不会重复处理
4. **进度显示**: 会显示总体进度和每个数据库的处理进度

## 后台运行（可选）

如果需要后台运行，可以使用 `nohup` 或 `screen`：

### 方法1：使用 nohup

```bash
cd /home/u2023103807/TACO/benchmark/generation/sql_filling

nohup python3 2fill_sql_placeholders_improved.py \
    --database_dir ../../data/beijing/database_chinese \
    --skeleton_dir ../../data/beijing/output/sql_skeleton \
    --graph_dir ../../data/beijing/output/graph_chinese \
    --output_dir ../../data/beijing/output \
    --max_retries 3 \
    > sql_filling.log 2>&1 &

echo $! > sql_filling.pid  # 保存进程ID
```

查看日志：
```bash
tail -f sql_filling.log
```

停止进程：
```bash
kill $(cat sql_filling.pid)
```

### 手动检查

```bash
# 查看已生成的SQL总数
find benchmark/data/beijing/output/single -name "generated_sql_*.json" ! -name "*_error.json" | wc -l

# 查看错误数量
find benchmark/data/beijing/output/single -name "*_error.json" | wc -l

# 查看各数据库的进度
for db in benchmark/data/beijing/output/single/*/; do
    db_name=$(basename "$db")
    success=$(find "$db" -name "generated_sql_*.json" ! -name "*_error.json" | wc -l)
    errors=$(find "$db" -name "*_error.json" | wc -l)
    echo "$db_name: 成功 $success, 失败 $errors"
done
```

## 注意事项

1. **API配额**: 注意API调用频率和配额限制，如果遇到429错误，可以：
   - 降低并发数（修改 `config.yaml` 中的 `max_workers`）
   - 等待配额恢复后继续运行

2. **断点续传**: 脚本会自动跳过已存在的文件，可以随时中断和恢复

3. **错误处理**: 失败的SQL会保存到 `*_error.json` 文件，可以后续单独修复

4. **磁盘空间**: 确保有足够的磁盘空间存储结果文件

## 配置调整

如果需要调整并发数或其他参数，编辑 `config.yaml`：

```yaml
llm:
  max_workers: 20  # 并发数，可根据API限制调整（建议10-20）

processing:
  max_retries: 3  # 最大重试次数
```
