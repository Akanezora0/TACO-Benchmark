# 跨数据库SQL生成组合策略

## 组合生成原则

### 1. 基于语义关联
- 优先选择语义相关的数据库组合
- 例如：企业服务 ↔ 社会保障（企业员工社保）
- 例如：医疗健康 ↔ 社会保障（医保相关）

### 2. 分层扩展策略
- **跨2个数据库**：从所有数据库中，根据语义关联选择约30种组合
- **跨3个数据库**：从2数据库组合中扩展，添加语义相关的第三个数据库
- **跨4个数据库**：从3数据库组合中扩展，添加第四个数据库

### 3. 均匀分布
- 每种组合生成相同数量的SQL
- 确保覆盖所有组合类型

## 组合数量规划

### 跨2个数据库
- **目标组合数**：约30种
- **每种组合生成**：约10-12条SQL
- **总SQL数**：约300-360条
- **考虑成功率43.5%**：需要生成约700-830个骨架

### 跨3个数据库
- **目标组合数**：约10种
- **每种组合生成**：约9条SQL
- **总SQL数**：约90条
- **考虑成功率43.5%**：需要生成约207个骨架

### 跨4个数据库
- **目标组合数**：约2种
- **每种组合生成**：约1条SQL
- **总SQL数**：约2条
- **考虑成功率43.5%**：需要生成约5个骨架

## 实现步骤

1. **生成数据库组合列表**：根据语义关联生成组合
2. **为每种组合生成SQL骨架**：使用轮询方式分配表
3. **填充SQL骨架**：使用大模型填充，允许优化
4. **过滤和统计**：只保留有执行结果的SQL

## 文件

- `database_combinations.json`：保存所有数据库组合
- 包含：2数据库组合、3数据库组合、4数据库组合
